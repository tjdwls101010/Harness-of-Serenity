## 3. KIND errors (rule ↔ principle)

Doctrine: **rule = invariant guardrail against catastrophic/irreversible error, true in EVERY situation. principle = teachable heuristic the embodied analyst re-derives per situation.** A rule that's really a judgment call rigidifies a rail and will mislead when the situation doesn't fit; a principle that's really an invariant leaves a catastrophic failure mode soft.

### 3A. KIND ERROR (principle → should be RULE): macro "Rate regime: never vibe it, never delete it" IS marked rule — CORRECT, but it lives in the wrong layer
- It is correctly `kind=rule` (it's an invariant against two model-native failures: vibing a gauge, deleting the rate angle). **But it's `placement=skill_body` in macro.** A "never assert a number from memory / never quote a regime without a sourced gauge" guardrail is a *number-discipline invariant* — the same family as claude_md's NON-NEGOTIABLE #2 ("never assert exact numbers from memory"). 
  - **Verdict:** the *general* invariant (never cite a macro number from memory; a dismissal of a stated regime requires a quoted gauge) should be **anchored as a claude_md non-negotiable** (it already is, as #2, generalized). The macro skill keeps the *specialized application* (the bidirectional rate-routing, honor-the-stated-regime, never-delete-the-angle) as a rule in skill_body — that's the right depth. **No change to kind; confirm the always-on number-discipline half is owned by claude_md and macro only specializes it.** macro's "Never cite a number from memory — macro gauges too" item (also kind=rule) is the bridge and is correctly placed. ✔

### 3B. KIND ERROR (rule → should be PRINCIPLE): analysis SECTION-6 "Always include an explicit bear case; never use 'certain'" — the bear-case half is over-rigidified as it stands, but "never certain" is a true rule
- Marked `kind=rule`. Two clauses bundled: (i) **never use "certain"** — a genuine invariant voice/honesty guardrail (true every time, catastrophic-honesty class) → correctly rule.
