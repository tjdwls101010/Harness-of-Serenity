# Amendments from implementing phase 04 — 2026-08-11

Phase 04 (the measurement instrument) was implemented on 2026-08-11, in the same session as the code layer. This file records where **04's own plan** was wrong or self-contradicting, in the same spirit as `08-amendments-260811.md`: the original phase file stays intact because it is the analysis as it stood, and overwriting it would hide that these were discoveries rather than foresight.

Everything here was confirmed by direct execution.

**Scope decided with the owner:** build the instrument (§4.1–4.7) and run a small pilot to prove it fires; exit criterion 6 — the trusted baseline that gates phase 06 — is deliberately left open as a pure spend decision with no build risk remaining. The full-baseline arithmetic is in §4.8 and unchanged.

## 4.6 — a `git worktree` has no Python, so every mode-B case would measure nothing

The plan says to run each mode-B case "in its own git worktree or a throwaway copy." **`scripts/.venv` is gitignored and has zero tracked files** (`git ls-files scripts/.venv` → empty). A bare worktree therefore contains no interpreter, every case's `scripts/.venv/bin/python scripts/serenity_pipeline.py analyze …` call fails, and the run produces answers built on no data at all — the exact "part of what the instrument measures is nothing" failure the phase exists to remove, reintroduced by the fix for a different problem.

The full-copy alternative the plan offers as an equal option is not equal: the repo is 477MB, 409MB of which is the venv.

**Implemented as** worktree + a symlink to the real `scripts/.venv`. The isolation the plan wanted, at 68MB instead of 477MB per case, with one shared read-only interpreter.

A symlink check must resolve the *target*, not the link: `os.path.exists` on a symlink pointing at a deleted directory is a naive pass. The runner executes the interpreter inside the worktree instead.

## 4.1 — the resolution gate drops two of the twelve gold cases it is supposed to guarantee

Exit criterion 1 asks for a sample that "yields zero unresolvable tickers **and** contains all twelve gold cases." Those two clauses contradict each other under the predicate the plan specifies (`marketCap` or `sector` non-null). Measured:

| gold case | yfinance | why the predicate rejects it |
|---|---|---|
| EWY (macro fear-fade) | `quoteType=ETF`, `marketCap=None`, `sector=None` | both fields are null for an ETF **by construction** |
| IQE (asset-value turnaround) | `quoteType=ECNQUOTE`, no marketCap, no sector | LSE-listed; yfinance wants `IQE.L` |

That is two of the six archetype categories the forced-include exists to protect, deleted by the gate meant to improve the same sample.

Both rejections are also *wrong on the merits*, which is the part worth keeping. Doctrine treats an ETF as a legitimate thematic vehicle, and the EWY case specifically tests whether the harness routes an ETF question to `macro` instead of `analyze` — a gate that drops it has the sampler overruling the doctrine it is measuring. The IQE case tests the foreign-winner / US-resolution-ladder move, so "it isn't US-listed" is the *subject* of the test, not a disqualification.

**Implemented as:** the gate gets an explicit ETF branch (for the random draw's benefit), and **gold cases bypass the gate entirely**. The gate's job is to stop the random draw feeding unresolvable garbage — SIVE, XFAB, ASHM and the `APPL` typo — into a run, not to second-guess a hand-picked case. A `yf_symbol` override (IQE → `IQE.L`) was considered and rejected: it would return GBP figures and route the case *around* the resolution-ladder move it was curated to test.

## 4.5 / 02.6 — the shared module is retired, not deferred a third time

02.6 was deferred out of the code layer into this phase because "its second consumer is built in 04.5." Reaching that point made a better answer visible: **`verdict_gate.py` already is the oracle.** It reads a JSON payload on stdin and returns a verdict, and `run_fixtures.py` regression-covers it.

Adding an `--explain` mode to the hook — same stdin, same `evaluate()`, structured per-check JSON out — gives the eval machine-readable structural scores with **one** implementation. That beats extraction on every axis the amendments file used to argue against it:

- No placement decision. `.claude` is not a valid Python identifier, so a module there is not importable from `scripts/`; a module under `scripts/` breaks the hooks wherever `scripts/` is absent. Neither problem exists when nothing is extracted.
- No drift. Extraction gives two consumers of one module, which can still diverge in *how they call it*; here the eval runs the production hook itself.
- The hook's 42 fixtures now regression-cover the eval's oracle for free.

**The property this rests on is tested directly:** for every verdict_gate fixture, `--explain`'s `decision` must equal what hook mode actually prints. Verified — 42/42 agree.

The mapping that matters: a `null` check means the hook did not *ask* the question, which is the rubric's `n/a`, never a 0. A macro-only answer names no company to run a driver line on, so `lens_line` is `null` — collapsing that to 0 would manufacture a miss out of a correct answer.

## 4.5 — a hook that cannot explain must read as unavailable, not as healthy

Found by running it. A `verdict_gate.py` predating `--explain` ignores argv, reads the same stdin, and prints ordinary hook output — **valid JSON that passes a naive parse**. The report then printed "mechanical pre-pass: 0/4 cases scored by the live hook" inside a line whose shape says everything is fine.

An instrument that degrades silently is precisely what this plan exists to remove, so `report` now demands the contract's own key (`checks`) and reports **unavailable** otherwise. The general form: parsing successfully is not the same as being understood, and the older the counterpart, the more likely it answers in a shape you accept.

## New work not in the plan

**The blind prompt's framing was mis-selected for 6 of the 12 gold cases.** `entry_type` picks the prompt template, so it decides what question each case *asks* — and the keyword heuristic reads a drop mentioned anywhere in a long thesis as a fear-dip. It turned the AXT InP chokepoint read, both NBIS reads and the SNAP margin-inversion read into "did it sell off?" questions, asked the cycle-stage meta post about a fear-dip on AEHR — testing none of the stage-placement-and-sizing it was curated for — and read CPSH's DoD-contract mention as an `event` when the thesis is a stage-1 discovery guess. The curated set now pins its own framing where the heuristic mis-frames it, plus a fourth `ranking` template for the meta case none of the three original templates fit.

That count was wrong in this file's first draft, which said five: the prose described only the fear-dip class and quietly dropped CPSH, whose mis-frame is `event`→`discovery`. Caught by a reviewer re-running `_entry_type` against the live DB rather than trusting the sentence. A hand-counted claim in prose drifts the moment a pin is added, so the count is now asserted by `test_curated_framing_overrides_the_keyword_heuristic` instead of only being written down.

This is the same defect class as 4.2's wrong-subject problem, one level up: 4.2 caught the eval asking about the wrong *company*, this catches it asking the wrong *question* about the right company.

**The subject heuristic was measured and deliberately left alone.** `_primary_ticker` takes the first regex-valid entry of the DB's `tickers` array — tagging order, not relevance — and it does pick NVDA for the AXT thesis and MSTR for the cycle-stage post. The obvious replacement, most-mentioned-in-content, was implemented and measured: **8/12 versus first-in-array's 10/12**, and on the random draw its three changes are mostly worse (it rewrites a Soitec thesis into an NVDA question). So only those two rows are pinned by hand and the heuristic stands. Recorded because the alternative *sounds* strictly better and the next person will propose it again.

**`notes` was write-only.** The judge has always been asked for a one-line "same insight / weaker / different-but-defensible," and `cmd_report` never read it — so the only field that can say "this case is broken" or "the setup resolved since" had no path to the report. That is why F17's failure mode had no visible symptom. Now surfaced per case.

**Answer-key leakage is now a test, not a convention.** `archetype`, `gold_tests`, `gold_label` and `thesis_text` are all answer key, and a leak into `blind_prompt` would fail nothing — it would quietly inflate every score. Asserted per case.

## Accepted limits in `--explain`, flagged by the agent that built it rather than discovered later

- **`stop_hook_active: true` reports every signal as `False`.** `main()` routes that case through `evaluate()`'s empty-message path instead of keeping a second hand-written "nothing to do" dict in sync, so the message genuinely is never read — the same thing hook mode does. Honest zeros beat computing signals nobody acted on. `report` always sends `stop_hook_active: False` anyway, so the eval never takes this path.
- **Malformed-stdin handling covers bad JSON syntax, not valid-JSON-wrong-shape.** A bare JSON array on stdin still raises an uncaught `AttributeError` from `data.get(...)`. That gap pre-exists in hook mode and was left alone rather than widened, per the surgical-change rule; `_hook_explain`'s "non-zero exit → unavailable" path degrades correctly if it ever fires, and it always sends a well-formed object.
- **`both_legs` is gated on `single_name and bear_leg`, not `bear_leg` alone.** The original code only ever computes the leg predicates inside `if single_name:`, so the brief's shorter phrasing was read as elided rather than as an override. No fixture exercises `bear_leg=True, single_name=False` — the vocabularies do not co-occur in the corpus — so this is an interpretive call, not a verified one.

## What the pilot found — the return on running it at all

Twelve real blind runs (n=12, seed 7, opus; report and scored JSON committed under `docs/eval/runs/`). Two **production** bugs in `verdict_gate.py`, neither covered by any of the 78 fixtures, both on checks the answer contract turns on:

- **A blank line after a bolded section header hid the section.** `**Downsides:**\n\n- real bullet` measured a body of `**`, failed the length bar, and nudged a correctly-formatted answer. The blank-line boundary was deliberate — it stops a section swallowing later prose — but it fired before the body had started. Every existing fixture happened to be written in the tight form, so the suite was green while the shape a model actually emits was broken.
- **The `Lens:` check read only the first occurrence.** A model that runs the lens properly routinely writes a header (`**Lens: RUN, both legs —**`) or states the formula before substituting into it, and puts the arithmetic below. This is the same unanchored-first-match defect `_find_section_header` documents at length — fixed there, never applied here, to the check N10 exists for. Widened to *any* occurrence, with the operator / `=` / digit still required on the **same** line so the marker cannot be assembled from fragments.

`any` rather than `last` is the one judgement call worth recording: a section header is matched in order to measure the body beneath it, so exactly one occurrence must be chosen as operative; this check asks whether at least one machine-checkable driver line exists, which is existential, and a forked lens legitimately emits two.

Fixing them moved the pilot's own numbers — pooled 91% → 95%, `lens_run` 75% → 92%, judge/hook disagreements 3 → 1. **That is the design working rather than a coincidence:** the eval's structural scores come from running the production hook, so a hook bug corrupts the measurement in the same motion that it corrupts production, and fixing it repairs both. The surviving disagreement (IQE: judge scored the lens as run; the answer contains zero `Lens:` lines) is the mechanical override doing precisely the job 4.5 specifies for it.

Also surfaced, and fixed: the sampler's `meta` never rode back through the workflow, so `report` printed `seed: None` — a run whose seed is unrecorded cannot be compared against another, which is the entire point of seeding. And 12 cases produced **82** one-off misses, which the report comma-joined into a single paragraph and buried the doctrine-delta section under.

## `args` reaches a workflow as a JSON-encoded STRING, and the failure is silent

Found while building the baseline. The labelling workflow returned `{"error":"no batches"}` on a call that passed a `batches` array — `args.batches` was `undefined` because `args` had arrived as a string.

The reason it is worth a section rather than a line: **the same bug had already silently altered the pilot.** That run was launched with `{n: 12, seed: 7, model: "opus"}` and its own log line reads `Sampling 6 cases (seed 7)` — `args.n` was undefined, so `n` fell through to the default of 6 and the sampler was invoked as `--n 6`. The run still executed, still produced twelve cases, and still reported sensible numbers, because the gold floor is twelve and 12 > 6. The requested parameter was ignored and nothing anywhere said so.

That is the shape worth remembering: a fan-out that receives no arguments fails loudly and gets fixed in a minute; one that receives *some* arguments and defaults the rest keeps running and quietly measures something other than what was asked for. The pilot's case set happened to be unaffected. At any n above the floor it would not have been.

Both workflow scripts now parse defensively (`typeof args === 'string'` → `JSON.parse`) and read every parameter from the parsed result.

## A forced-choice taxonomy hides its residue in the broadest bucket

Found while freezing the standing sample, and the most transferable thing in this file.

The archetype-labelling pass was told, in the prompt, *"Pick the single best fit. Every case gets exactly one label; there is no 'unclear' option."* The intent was to stop a labeller hedging. What it actually produced: **36 of 88 cases came back `cycle_meta`**, and reading their own stated reasons, that bucket had absorbed everything that is not one name's argument — including six posts that are not investment theses at all. A five-ticker idea-share list of bare one-liners. A table of 23 tickers' daily moves after an earnings print, where the tagged ticker is not even in the table. A follower-milestone thank-you note.

Why it is not a cosmetic labelling error: the eval turns each case into *"as of {date}, what's your read on {TICKER}?"* and scores the reply against that post as the answer key. Against a post ranking 23 newsletter authors by return, **every rubric row is a miss** for reasons that have nothing to do with the harness. That is this phase's own opening failure — "part of what the instrument measures is nothing" — arriving through the fix for a different instance of it. And it is worse than a missing case, because a low score looks like a finding.

The general shape: **removing the escape hatch does not make labels more decisive, it relocates the uncertainty into whichever category is broadest and makes it invisible.** The residue does not stop existing; it stops being countable. A taxonomy applied to real-world data needs a way to say "none of these," and the count in that bucket is a measurement in its own right — here it says 41% of a random draw from this DB is not a single-name thesis, which is corroborated by the corpus's own coverage stats (ranking list-posts ~13%, thematic/comparison ~51%).

Fixed by a second triage pass over that bucket alone with an `exclude` verdict available, and an `excluded` list in the label file that the sampler skips. Two properties are tested rather than assumed: an exclusion is **back-filled** (n stays what was asked for, so an exclusion costs sample composition rather than sample size), and exclusion **cannot reach a gold case** (the curated floor is hand-picked and its archetype spread is the entire point).

## The same defect three times, in three disguises

Freezing the standing sample took three passes, and each one found a version of one defect: **the case asks a question its answer key cannot answer.**

1. **Wrong archetype scope** — fixed by labelling. The two chokepoint-scoped rubric rows had an effective in-scope N of 4 without it.
2. **Not a thesis at all** — fixed by triage. 26 of 88 random cases were a five-ticker idea list, a table of daily moves, a follower-milestone note.
3. **Right thesis, wrong company** — fixed by a subject audit. **19% of the random cases** asked about a name their thesis merely mentions: a thesis arguing SIVE filed under AMD, one arguing LITE filed under GOOGL, one whose chokepoint is Macronix/Winbond filed under NVDA.

The third is the instructive one, because the first two passes had already read every one of those theses and did not flag it. The labelling pass described the THESIS — its own recorded reasons literally read *"despite the AMD tag"* and *"HIMX is merely the earnings-call catalyst"* — and the triage asked whether the POST is scoreable. **Neither ever asked whether the SUBJECT was right**, so a well-argued thesis about company X tagged with company Y passed both cleanly, carrying an admission of the defect in its own justification text.

The transferable form: *a pass finds what its question asks for, and a reviewer reading its output will absorb the framing rather than audit it.* Three passes over the same data found three disjoint defects not because the data was unusually bad, but because each pass asked a different question. When output text contains an aside like "despite the AMD tag," that aside is a finding the pass had no field to report.

A re-subject target that does not resolve is EXCLUDED rather than pinned — four of the six pointed at foreign codes (7853, 3363, P4O) or an unresolvable line (SIVE), and swapping a wrong-company question for a no-data one is the same failure in a different costume.

Net effect on the standing sample: n=74 → **63**, chokepoint 21 → **17** (still above the n-floor of 12). The "chokepoint 21" figure reported earlier in this session was not sound and is corrected here and in every doc that carried it.

## The panel is a census, not a seeded sample

Also worth correcting in writing, because the command itself invites the misreading. `sample --n 100 --seed 7 --only-labeled` returns the **whole labelled set** — 63 cases exist and `--n 100` asks for more, so every one is taken. Seeds 7, 99 and 12345 produce identical membership and differ only in ordering.

That is the right shape for a regression panel: you want the same cases every time. But it means the panel supports statements about **itself**, never about the corpus — no prevalence, no representativeness, no "the harness reproduces X% of his method." Say "the standing panel scored X." The `--seed 7` sitting in the command made the wrong reading more plausible, which is exactly why it needs saying out loud.

## Still open, deliberately

- **Exit criterion 6 (the trusted baseline).** NOT run. A 74-case mode-A pass was launched and **stopped by the owner within 8 blind runs**: 149 opus agents is not a reasonable ask of one account, and a session limit had already killed an earlier run the same evening. That was a scaling error on my part — I took the plan's n≈60–100 as the target without re-checking it against the budget that actually binds.
  The honest post-mortem is that the number was the wrong goal anyway. The *aggregate* is the weak half of this instrument: the report itself states that a per-move before/after claim is unsupportable at any realistic n, and the pilot's doctrine-delta section returned "no move missed in ≥2 cases" — zero actionable deltas — alongside 82 one-off items. Every finding that actually mattered came from **reading the answers**: two production hook bugs out of twelve blind runs, and the sample defects out of reading labels. That value saturates early and then flattens, so n=74 buys a more precise version of a number already documented as untrustworthy.
  The panel and the command are ready. Run it when budget allows, and treat the blind runs as a bug-finding corpus first and a rate second.
- **A codex arm was considered and declined.** Codex has effectively no limit here and does load the spine (`AGENTS.md` → `CLAUDE.md`, verified). But the eval asks whether **this** harness reproduces the method, and the harness in production is Claude+Opus — a codex arm measures a different agent, which is §4.7's model-pinning confound at maximum. It would only answer the doctrine-vs-model question against a Claude arm on the same cases, and the Claude arm is the one that cannot be afforded. Two mechanical blockers besides: codex's `read-only` **and** `workspace-write` sandboxes both block network, so the pipeline returns empty `key_facts` and the run measures nothing; restoring it needs `danger-full-access`, which also lets the run write into the live `sessions/`.
  One free datapoint came out of the smoke test anyway: with **zero** pipeline data, codex still produced the method's shape — TLDR, type-B routing, an explicit evidence boundary, the balance-sheet identity check, two `Lens:` lines, NFI/NFA — and refused to substitute web figures (N3) rather than fill the gap.
- **Build and pilot only, by decision (superseded above).** The full run is ~5–9M tokens at the plan's split (mode-A n≈60–100 + mode-B n≈15–20), measured per-case at CLAUDE.md 8.1K tok + one skill 6.7–16.6K + an `analyze` payload 4.1K, plus the agentic loop.
- **Tracing `Lens:` numbers back to that case's captured `key_facts`** (§4.5's "strengthen further where it is cheap"). It is not cheap here: capturing `key_facts` per case means schema-forcing the blind-run stage's output, and squeezing a full in-character answer through a structured field risks degrading the very thing being measured. Deferred with that reason rather than half-built.
- **Archetype labels for the random remainder.** By design: they get filled during the one-time human inspection that freezes a standing sample. Until then `report` counts those cases separately and flags them as scope-unstable rather than pretending the split is mechanical.
