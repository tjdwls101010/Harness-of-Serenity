# Harness spec — Serenity

The record of what this harness is and why each piece sits in the layer it sits in. Regenerated 2026-07-09 from disk + the design-review plan (`.tmp/plans/2026-07-09-harness-design-review-plan.md`). The next audit compares against this; keep it in sync with every component change.

## Goal

Make Claude embody "Serenity," a supply-chain-architect equity analyst, reproducing his *method* (map where economic power structurally concentrates before consensus prices it; name the archetype, run the winner-gates, run the demanded valuation lens with arithmetic, rate the name) — not a fixed set of past calls. The one design invariant everything serves: **code loads facts, Claude judges.** Deterministic code loads the objective numbers (yfinance financials, SEC XBRL disclosure) so no judgment is baked into code where it would drift silently run-to-run; every verdict, archetype tag, and rating is Claude's.

## Design thesis (the standard every component is held to)

Serenity's methodology is tacit — it cannot be enumerated "case X → action Y." So:
- **Facts** (enumerable, verifiable) → deterministic code, identity checks, structural output-contract checks.
- **Judgment** (not enumerable) → re-derivable principles with their *why*, worked examples / war stories, and the model's own intelligence.
- **Reproduction assurance** (can't be added by more rules) → measurement (the §5 eval), where a missed move feeds back as a *generalized* principle, never a new case-rule. Bloat's root cause is per-miss patching (a miss → a case-targeted rule → the spine grows → the 17th case still uncovered); the cure is generalization, not accretion.

## Layer routing — what lives where and why

| Layer | Holds | Why here |
|---|---|---|
| **CLAUDE.md** (spine, always loaded) | voice, the six roots + ten values, the archetype funnel + routing reflexes, the five/six pre-answer checks, the answer contract (A/B/C/D/E templates + the `Lens:` line), the ten non-negotiables | every session needs these; the bar for a line is "does literally every turn need it" |
| **skills** (`.claude/skills/*`, on-demand) | the situational depth that bites once the JSON is in front of you — macro (regime + catalyst), discovery (find a US-listed name), analysis (gate/value/time/rate one name) | triggered by `description`; body loads only when the question type needs it |
| **hooks** (`.claude/hooks/*` + `settings.json`, deterministic) | the four points where determinism earns its process cost — session-start self-check, prompt-time action nudge, post-analyze identity tripwire, answer-end verdict contract | advisory layers can be skipped under output pressure; a hook fires regardless |
| **agents** (`.claude/agents/*`, context-isolated) | the filing's honest reader (`serenity-filings`) — objective relationship facts verbatim, no judgment; and the per-name scorecard filler (`serenity-scorecard`) — one ticker's fixed scorecard during a rank-N fan-out, cohort-blind | context-hungry read-heavy roles where only the extracted facts / the one scorecard come back; the scorecard agent also PINS byte-identical per-name instructions so a ranking is reproducible run-to-run |
| **pipeline** (`scripts/`, deterministic) | the fact loader — `serenity_pipeline.py` (yfinance financials + macro gauges), `serenity_filings.py` (edgartools XBRL for the agent). `pipeline/legacy/` is the quarantined judgmentful old pipeline (reference only) | numbers must be byte-stable and judgment-free; the seam drops every judgment label before the agent sees the evidence |
| **session archive** (`sessions/`, git-tracked, convention in CLAUDE.md) | durable analysis memory — one scorecard per name, `_ranking.md`/`_macro.md` per basket, verdict-free `INDEX.md` retrieval; numbers-expire + fresh-judgment-first rules | cross-session memory turns run-to-run variance into tracked conviction updates (V9) and makes post-mortems (V7) possible; stored as prose, enforced softly by verdict_gate's `Saved:` mark |
| **eval** (`scripts/serenity_eval.py` + `scripts/eval/`, user-triggered) | the reproduction-measurement harness — sampler + rubric + report (deterministic) and a blind-run/judge workflow (token-spending); measures method reproduction on real past theses | not runtime; reads the thesis DB as an answer key, so explicit-trigger only (N8) |

## Components

**CLAUDE.md** — the spine. Self-contained doctrine; the skills rely on its non-negotiables and never restate them.

**Skills (3)** — `serenity-macro` (`.claude/skills/serenity-macro/`; aggression dial + catalyst gate), `serenity-discovery` (`.claude/skills/serenity-discovery/`; finding an under-priced US-listed name; owns chain-tracing, the DEDUCED-vs-CONFIRMED discipline, the US-listed resolution ladder), `serenity-analysis` (`.claude/skills/serenity-analysis/`; the single-name engine; owns the archetype playbooks, winner-gates, valuation lenses, the falling-knife 4-step, entry/vehicle/kill, and the **Rank-N protocol** — the fixed decompose-a-basket procedure: gates filter, stage rung orders/sizes, gate-strength+conviction within a rung, cohort-independent tiers, delta reconciliation). Organized by funnel step, not archetype — the valuation lens forks on capital structure, which cuts across archetypes, so an archetype split would not reduce load.

**Hooks (5)** — `session_status.py` (SessionStart: runs `serenity_harness.py validate`; silent when green, loud when red, when it CRASHES, and when it times out — those last two used to share the silent path with "healthy", so the harness reported perfect health precisely when its health check was broken), `scorecard_guard.py` (PostToolUse/Write|Edit|MultiEdit: soft-flags a `sessions/**/TICKER.md` whose frontmatter misses the pinned schema, at the moment the pipeline output is still in context; it shells out to `scorecard-lint` rather than restating the field list, so the schema has one definition and the path filter lives in the script — an `if:` glob in `settings.json` would be invisible to the fixture suite, which pipes payloads straight to the hook), `evidence_discipline.py` (UserPromptSubmit: three just-in-time actions — pipeline-first, dated-catalyst scan, lens-at-intake — plus a fourth retrieval nudge to reconcile deltas against `sessions/INDEX.md` after fresh scorecards, plus a meta/dev-prompt false-fire guard), `data_integrity_guard.py` (PostToolUse/Bash: recomputes balance-sheet identities after `analyze`, flags a phantom/stale/collision number), `verdict_gate.py` (Stop: a STRUCTURAL contract — hard-blocks a market verdict missing NFI/NFA; soft-nudges a valuation verdict missing the `Lens:` driver line, running only the bear leg, or missing a valid non-empty `Saved:` session-archive mark). All exec-form in `settings.json` (an `args` array, not shell-form — shell-form let a shell-profile banner silently no-op a JSON-emitting hook).

**Agents (2)** — `serenity-filings` (`.claude/agents/serenity-filings.md`; tools: Bash, Read, Grep): extract-never-judge, silence is null, quote + cite. `serenity-scorecard` (`.claude/agents/serenity-scorecard.md`; tools: Bash, Read, Grep, Write): fills ONE name's fixed scorecard during a rank-N fan-out — runs the pipeline, applies archetype/gate/stage/lens judgment, writes `sessions/{folder}/TICKER.md`; cohort-blind (never reads a sibling scorecard or a prior session), assigns no tier. Its body is the single source of truth for the scorecard schema; the launch message is pinned separately by the Rank-N protocol's template.

**Lens CLI** — `scripts/serenity_lens.py`: one subcommand per doctrine-named valuation driver, emitting the verified `Lens:` line the answer contract requires. Not justified by arithmetic correctness — the model multiplies fine at this scale, and if that were the case this would be ceremony. Three things earn it: `--from-run` pulls the market cap from a saved `analyze` payload, so the doctrine's most-repeated numeric warning becomes structurally unavailable rather than rule-enforced (a hand-typed `--mc` still works, labelled UNVERIFIED — the point is to make an unverified denominator *visible*, not forbidden); a subcommand set plus a genuinely usable `custom --expr` converts a closed driver list into an open space that still teaches the shape; and `--fork floor|upside` makes "both legs ran" checkable, where running only the bear leg is named in the doctrine as the single biggest direction-miss.

The C1 seam is enforced by test, not discipline — this is the component most likely to drift into judgment-in-code. The argument surface never accepts a ticker or an archetype (the test introspects the argparse tree, so a flag added later is caught too), the output never contains valuation vocabulary, and the tool never selects which lens applies. Both guards were verified failing before being trusted.

**Sector map** — `scripts/serenity_sectormap.py` (schema `serenity_sectormap/1`, one `_sectormap.json` per session folder): a read-only loader/validator for a chain map — `validate` / `show` / `layers` / `tickers` / `cohort` / `diff` / `index`. It never runs the pipeline; `cohort` only *builds* the `discover` argv. Adopted 2026-08-11 having been written in a side session and left untracked, absent from this spec, and named in no doctrine file — which is the same as not existing, because the model has no way to learn a capability nothing points at. **Adding a component is not done until it is committed, specced, and reachable from doctrine**; treat that as the completion bar, not a courtesy.

`cohort` carries each candidate's `role`/`note` beside the argv. It used to emit the argv alone, which dropped the field that qualifies a ticker — the map disclaims some names as theme exposure rather than bottleneck ownership, and `discover` is the comparator whose cross-peer ratio the doctrine reads as the verdict, so an unqualified list lets a conglomerate rank against a pure-play as if the map had called them comparable.

Deferred deliberately: a `relationship: owner | tool | consumer | adjacent_proxy` field with a `--include-adjacent` opt-in. `_validate_object` treats the candidate field set as both **required and closed** and `load_map` *raises*, so adding a field would put the one real map (100 candidates, none carrying it) into 100 violations and take `show`/`layers`/`tickers`/`cohort`/`diff` from working to dead — not just `validate`. It also needs 100 tickers classified by judgment against a real archive. Do it with the migration, or add optional-field support to the validator first; do not add the field alone.

**Validator** — `scripts/serenity_harness.py validate` (spine + skills present, pipeline imports, the fact/judge seam, the hook wiring, the SEC layer, the reproducibility layer — the scorecard agent's frontmatter + schema sentinels, the session-archive doctrine in the spine, the verdict-free `INDEX.md` — and the hook fixture suite's own exit code). No check count is quoted here on purpose: a number in prose has to be restated to stay true, and this spec shipped `22/22` while the suite was at 19/22. Plus the deterministic `rankdiff A_ranking.md B_ranking.md` subcommand — diffs two tier tables (per-ticker tier A→B, agreement %, only-in-A/B, tier-cut delta); pure fact-loading, no judgment, so every repeat-ranking in the archive yields a free reproducibility measurement.

**Mirror** — `AGENTS.md` → `CLAUDE.md` (symlink), so an AGENTS-convention CLI loads the same spine with no drift. That is the whole mirror. (`.codex/` was retired 2026-08-11 and the `.agents` → `.claude` symlink 2026-07-09.) The `.codex/` layer is worth one line of history because of *how* it died rather than that it did: its `hooks.json` hardcoded an absolute path, so when the repo moved out of `~/Documents/` every binding went inert — silently, since a hook that never fires and a hook with nothing to say produce identical output. It stayed dead long enough to be documented as a known limitation and still not fixed. A mirror maintained by hand costs a translation per component and pays only while someone is actually running the other CLI; a symlink costs nothing and cannot drift. Prefer the symlink, and if a format genuinely can't be symlinked, ask whether that surface is worth mirroring at all.

## Validation

- `scripts/serenity_harness.py validate` → green; `rankdiff` diffs two `_ranking.md` tier tables deterministically.
- Hooks: fixtures committed under `.claude/hooks/tests/`, one JSON stdin payload per scenario. Each carries its own `_expect` and lives in a directory named for the hook it exercises, so `run_fixtures.py` discovers both the hook and the assertion — there is no central case list to append to, and README.md documents rather than defines. A fixture without `_expect` fails loudly; a skipped fixture would be indistinguishable from a passing one.
- Pipeline: `scripts/tests/test_evidence_contract.py` (the fact/judge seam is judgment-free) + a fixture-based `evidence --fixture` smoke. Run with `scripts/.venv/bin/python -m pytest scripts/tests/ -q`; the venv has been relocated, so its `bin/pip` and `bin/pytest` console scripts carry a dead shebang and everything routes through `-m`.
- Reproduction: `scripts/serenity_eval.py` — baseline before a doctrine edit, re-run after, compare per-move rates.
- **Prose-growth baseline**: always-loaded 27,451B · on-demand skills 109,186B, taken at `a35c9a3` (2026-08-10). `validate`'s `prose_growth` check warns past +15% on either figure. It is a signal, never a cap — length limits here are advisory and content that belongs always-on stays. When a warning is examined and accepted, say why in the change history below and move the baseline in `serenity_harness.py`; the two halves are measured separately because always-loaded is billed every request and a skill body only when its trigger fires, so merging them would hide which one moved. Verified firing at +19.8% before being committed.
- **The red path is exercised, not assumed** (2026-08-11). A check nobody has watched fail is not a check — this harness reported 15/15 green for as long as its fixture suite sat at 19/22. All four paths were driven deliberately and observed: a hook regex edit (`\bNF[IA]\b` → `\bNFIA\b`) reddens `validate`, exits 1, names the failing fixture, and makes `session_status.py` loud; a validate that crashes without parseable JSON is now loud rather than silent; a fixture with no `_expect` hard-fails rather than skipping; a fixture directory with no matching hook hard-fails. **Re-run this whenever a check is added.** The failure mode being guarded against is not a check that fails wrongly — it is a check that cannot fail at all, which looks identical to a check that passes.

## Change history

**2026-08-11** — remediation, code layer (plan `docs/plan/260810/`, phases 00–03 + 07; read `08-amendments-260811.md` alongside it, four plan items were factually wrong). The finding that reframed the whole exercise: **the harness's most carefully-designed reproducibility mechanism produced output matching its own schema in zero of seven real cases, and every automated check reported green.** So the work was not to add better doctrine — an addition would have been equally unobserved — but to make a failure visible on the execution path.

- **The self-check can now go red, and has been watched doing it.** `validate` gained `hook_fixtures`, which runs the committed suite and adopts its EXIT CODE (never a parsed count — a hardcoded expected number rots the moment anyone adds a fixture, and asserting a literal instead of a behavior is the defect this same pass removed from `sec_consolidation`, whose two extra conjuncts were `True` by construction for every possible input). Verified: a one-character hook regex edit reddens `validate`, exits 1, names the failing fixture, and makes SessionStart loud. Before this, that edit produced 15/15 green and silence.
- **`session_status.py` distinguishes three failures.** Red / crashed / timed out, where a bare `except` used to map "healthy and green" and "crashed with a traceback" onto identical silent output — the harness reporting perfect health precisely because its health check was broken, and the louder the breakage the quieter the hook. A timeout became a signal rather than a non-event the moment the fixture suite moved inside `validate`.
- **Fixture scaffolding left `sessions/`,** which is documented as real archived analysis; debris there invites the tidy-up it got (both folders deleted, three fixtures red, `validate` green throughout). `run_fixtures.py` now sets `CLAUDE_PROJECT_DIR` to its own sandbox EXPLICITLY — relying on the hook's `or os.getcwd()` fallback passes in a terminal and fails at every real SessionStart, a trap invisible exactly where you test it.
- **Fixtures self-describe.** The directory names the hook, an `_expect` key carries the assertion, and a fixture without one hard-FAILS rather than skipping. Adding a fixture touches one new file, which is what made a four-agent fan-out safe. `22/22` had appeared in nine documents while the suite was at 19/22; counts are now printed, not asserted.
- **Hook contract, all three failure directions** (`verdict_gate`): entry no longer gated on the literal TLDR token (a full verdict opening "Bottom line:" produced *empty* output, every check dead behind one `if`); a label with a negating body no longer passes (`Downsides: none that matter` was silent — left alone, the check trains compliance tokens); the `Lens:` marker checks that an arithmetic expression is present, not a specific operator, since the doctrine writes `replacement-cost/unit` with a slash and prices sum-of-parts as pure addition. Numeric bar is line-level, not per-operand — per-operand inverts the suite's only "a correct answer is silent" fixture.
- **False fires** (`evidence_discipline`): bare pipeline field names (`valuation`, `earnings`, `dividend`, `PT`) dropped from the market-anchor override — they appear in every prompt *about* the pipeline's code, so they cannot distinguish. **Magnitude tiering** (`data_integrity_guard`): a 142% revenue-field gap no longer logs at the same severity as a benign 12%, with the 75% threshold *derived* (a company doubling revenue YoY at maximum TTM-vs-annual staleness produces exactly 75% through timing alone).
- **New:** `scorecard-lint` + a `scorecard_guard` write-guard (one schema definition; the hook shells out rather than restating it, and the path filter lives in the script because an `if:` glob in `settings.json` is invisible to the fixture suite by construction); `harness new-session` (slug rejected at the argument boundary, date from wall-clock); `serenity_lens.py`; `serenity_sectormap.py` adopted; `rankdiff` returns JSON and canonicalizes tiers.
