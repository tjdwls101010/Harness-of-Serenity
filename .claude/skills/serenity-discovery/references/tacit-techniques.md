# Tacit finding-techniques — the full catalogue

Load this when an axis (vertical chain-trace / horizontal transfer) hasn't surfaced the node and you want another way to point at where attention hasn't reached. Each is a distinct probe; reach for the one the situation fits. All rest on **R3** (CLAUDE.md): attention pools on the visible end-node, so the value is wherever it hasn't.

## 1. SEC competitor-list mining
**What:** Read a known winner's 10-K competitor list as a pre-vetted *discovery* candidate pool — smaller, earlier names in the same chain, vetted by the filer's own counsel as genuinely competitive.
**Why:** Almost no one reads a 10-K for the filer's *rivals* — they read it for the filer — so the competitor list is free, pre-vetted diligence on the chain, sitting unused as a discovery tool.
**Caveat (gotcha):** a *named* competitor is by definition visible enough to be named, so the list is a starting pool, not the endpoint — the confidential reconstructed A→C link is the higher prize.
> Picture: a leading optics maker's filed competitor list, read years early, held several names that later 20×'d.

## 2. The analyst-report gap — read for the omission
**What:** Read institutional reports for the *omission* — the supplier clearly in the chain but NOT on the list. "Institutions haven't found it yet" is exactly where the highest returns are; the names *on* the list are already priced.
**Why:** This inverts how reports are normally consumed — the value isn't in what the analyst covered (already priced into every name on the page) but in the chain-position the analyst left blank. The omission is a direct readout of where attention has *not* reached, which (R3) is where mispricing lives. A competent reader stops at the named names; the edge is treating the gap as the signal.
> Picture: "read institutional reports for the omission... 'institutions haven't found it yet' is exactly where the highest returns are."

## 3. The re-rating anomaly
**What:** A whole ecosystem up hundreds of percent but one *critical* node still flat/small = the undiscovered gem. Ask *why* it hasn't moved — usually a coverage gap, not a flaw.
**Why:** A critical node that didn't re-rate while its ecosystem did is a pure attention-lag signal — but the "ask why" guard is essential. A flat node can be flat because it's broken (deserved) or because nobody's looking (exploitable), and conflating the two is how you buy a falling knife dressed as a gem. The anomaly *generates* the candidate; the why-test *qualifies* it.
> Picture: IQE (DB `2027318568728273305`) — owns 100+ MOCVD reactors, ecosystem re-rated but IQE still priced for bankruptcy on £45M debt; the "why" = coverage gap + balance-sheet fear, not a capacity flaw.

## 4. Second-order beneficiary
**What:** From a catalyst, trace who supplies the supplier that just maxed out. A demand blowout at tier N forces tier N+1 from afterthought to bottleneck.
**Why:** The market prices the obvious beneficiary (the company that reported) and stops; the supplier-of-the-supplier is a separate data point nobody connects, so its forward revenue moves before its price does. The move is mechanical: when a node maxes out capacity, its own inputs become the new constraint — demand has nowhere to go but down one more layer.
> Picture: a transceiver maker's demand blowout → the epi-reactor makers it must now buy from go from afterthought to bottleneck.

## 5. Convergence-find
**What:** List the obvious players in a theme, then ask "which single company do *most* of these rely on?" That common dependency is often the real chokepoint.
**Why:** A node multiple visible players all depend on is, almost by construction, a chokepoint — yet the market prices each player separately and never aggregates the shared dependency into the single node's value.
**Doubles as a tail-risk check (gotcha):** the same aggregation that finds the alpha exposes the danger — a "diversified" set of names that all lean on one node is secretly one bet. Read it both directions; the shared node is both the alpha and the single-point-of-failure. (Macro owns the bear-case/basket-risk reading of the same fact.)
> Picture: a single-island foundry cluster or one country's refining that a whole basket of US-listed names quietly shares.

## 6. Government-blueprint mining (candidate generation only)
**What:** A published industrial-policy blueprint or supply-chain impact-analysis is a free, pre-vetted, often *ranked* list of a chain's controllers — sometimes with explicit control percentages no screen will hand you. Mine it for the *names*; it is a candidate-generation source.
**Why:** A government that publishes a supply-chain analysis has already done the expensive diligence — identifying which nodes are critical and who controls them, sometimes with control percentages — and almost no one reads that document as a *screen for names*. It hands you a ranked controller list the market hasn't aggregated.
> Picture: CPSH (DB `2016921538780680402`) — AlSiC pure-play (~25% Western share) surfacing as a DoD-relevant thermal material in a defense blueprint; the document names the controller before any screen would.
(The catalyst/floor read of the same document — datable lagged repricing, chokepoint-validation, two-governments-compound — is owned by macro's subsidy-signal item; this generates the candidate, macro reads it as a catalyst on a name in hand.)

## Specialization — undisclosed defense / national-security chains
**What:** For undisclosed defense/national-security chains, match a prime's new-program specs — ruggedization, temperature range, edge-AI — to small-caps announcing contracts with an unnamed "leading defense" customer.
**Why:** Classified/sensitive programs structurally suppress the customer name on *both* sides, so the link is *never* in a filing — but the prime's program specs and the small-cap's "unnamed leading customer" press release each leak one half, and the spec-match is the only way to draw the line. This is the confidential A→C reconstruction move (see SKILL.md) specialized to a sector where disclosure is legally constrained rather than merely strategic — so the spec-match isn't an optimization, it's the *only* available route.
> Picture: small-caps announcing contracts with an unnamed "leading defense" customer, pinned by ruggedization / temp-range / edge-AI spec-match to the prime's new program.
**Invariant reminder:** a spec-match deduction is DEDUCED — a lead, not a thesis. Size nothing until a filing, release, or conference confirms the customer (see SKILL.md invariants).
